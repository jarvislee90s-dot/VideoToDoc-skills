## 1. 目标与背景

### 1.1 目标

向 **TRAE AI 创造力大赛** 提交一份"创意产物 HTML"作为报名作品。HTML 同时承担两个角色:

1. **报名创意展示** — 让审核员看清创意(满足报名帖四部分要求),一次审核通过
2. **动态使用说明书** — 让看到 HTML 的真实潜在用户能照着把 VideoToDoc 用起来

### 1.2 关键约束(来自大赛报名帖 /t/topic/22548)

- 适用阶段: 报名 2026-06-16 ~ 2026-07-15
- 报名帖必须包含四部分正文: 创意名称+介绍 / 目标用户及痛点 / 价值与意义 / 附带 HTML
- HTML 标签: **学习工作**(四选一)
- HTML 文件: 上传到社区报名帖, 单文件 20M 以内
- 报名审核只看合规(赛道匹配 + 发帖要求), 不评创意好坏

### 1.3 项目背景

VideoToDoc 是一个把课程 / 讲座 / 培训视频转成图文讲义的本地工作流, 包含三个 Skill:

- `video-summary` — URL/本地视频 → 字幕或 ASR → transcript
- `video-to-slides` — 视频 + transcript → 截图去重 → 图文对齐 → Markdown / Word / 思维导图
- `feishu-markdown-publish` — Markdown → 飞书云文档

项目已开源在 GitHub, 三个 Skill 已稳定可用。

## 3. 页面内容结构(7 段叙事流)

每段都是单页滚动的一屏, 通过 IntersectionObserver 触发"当前步"状态。

### §1 Hero

- 顶部标签: `🎓 学习工作赛道 · 创意提案`
- 主标题: `VideoToDoc` (粉色强调字)
- 副标: 把课程、讲座、培训视频, 一键变成图文讲义
- 一句话特性: 自动转录 · 截图去重 · 图文对齐 · 飞书发布
- 双 CTA: `开始使用 →` (粉实心) + `★ GitHub` (黑描边)

### §2 创意介绍(对应报名帖第 1 部分)

- 痛点: 培训视频看完一遍就忘, 找内容靠拖进度条
- 动机: 把视频转成可检索、可标注文档
- 产品形态: 本地 CLI 工具链 + 飞书云文档

### §3 目标用户及痛点(对应报名帖第 2 部分)

- 核心用户: 培训学员 / 课程学生 / 知识工作者
- 场景: 看完长视频后想沉淀笔记
- 痛点: 手动记笔记效率低; 视频无法检索; 团队内知识不沉淀

### §4 价值与意义(对应报名帖第 3 部分)

- 效率提升: 1 小时视频 → 5 分钟生成完整图文讲义
- 知识沉淀: 讲义入库可搜索可分享
- 落地成本: 本地运行, 免费, Apple Silicon 优化

### §5 怎么用 · 三步工作流(滚动联动 + 吸顶进度)

吸顶进度条: 01 视频转文字 · 02 截图对齐 · 03 发布飞书

- **01 视频转文字**
  - 机制: 字幕优先 → mlx-whisper 本地 ASR fallback
  - 命令: `python3 .agents/skills/video-summary/scripts/process.py "视频URL"`
  - 产物: `transcript.json` + `transcript.txt`
- **02 截图对齐讲义**
  - 机制: 三段式去重 + 毫秒级图文对齐
  - 命令: `python3 .agents/skills/video-to-slides/scripts/process.py video.mp4 --transcript transcript.json`
  - 产物: `讲义.md` + `讲义.docx` + `思维导图.mmd/.png`
- **03 发布飞书**
  - 机制: 解析 Markdown 章节, 逐页上传飞书
  - 命令: `python3 .agents/skills/feishu-markdown-publish/scripts/publish.py 讲义.md <space_id>`
  - 产物: 飞书云文档 URL

## 4. 视觉系统

### 4.1 配色

| 角色 | 色值 | 用途 |
|------|------|------|
| Primary | `#FB7299` | 品牌主色, 强调字, 主 CTA, 进度条, 序号 01 |
| Secondary | `#00AEEC` | 辅助, 序号 02 |
| Success | `#00B894` | 第三色, 序号 03 |
| Background | `#FFFFFF` | 卡片 / Hero |
| Surface | `#F4F5F7` | 页面背景 |
| Text Strong | `#18191C` | 标题 |
| Text Muted | `#61666D` | 正文 |
| Border | `#E3E5E7` | 卡片描边 |
| Code BG | `#F4F5F7` | 代码块底色 |

**严格禁用**: 任何 `linear-gradient` / `radial-gradient` 渐变; 装饰光晕球 / 模糊圆。

### 4.2 字体

- 主字体: `-apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`
- 等宽: `"SF Mono", Menlo, monospace` (用于代码块、序号、统计数字)

### 4.3 形状

- 卡片圆角: `8px`
- 按钮圆角: `6px` (B 站风, 不是胶囊形)
- 标签: `4px`
- 序号: `6px` 圆角方块(等宽数字)

### 4.4 间距

4 / 8 / 12 / 18 / 24 / 32 / 48 dp 系统化节奏。

### 4.5 动效

- 滚动联动: IntersectionObserver 切换"当前步"状态(进度条 + 序号高亮)
- 元素入场: `opacity + translateY(20px)`, 300ms ease-out, 仅首屏出现一次
- 按钮: hover 时背景色加深一档, 150ms
- **禁用**: 任何会动布局的动画(width / height); 装饰性持续动效

## 5. 技术约束

### 5.1 单文件交付

- 一个 `index.html` 文件, **所有 CSS / JS / 字体 / 图片全部内联**
- 不引用任何 CDN 外部资源(Discourse 上传后可能无法访问外网)
- 字体用系统字体栈, 不引 Google Fonts
- 图片优先用 SVG(代码写), 或真实产物 base64 内联

### 5.2 大小限制

- 硬上限: **20 MB**(社区发帖限制)
- 实际目标: < **2 MB**(没有真实视频, 没有大图)
- 如果真实产物样例过大, 用缩略图 + 链接代替

### 5.3 浏览器兼容

- 现代浏览器(Chrome 100+ / Safari 15+ / Firefox 100+)
- 移动端可读(响应式, 但不要求移动端完整体验)

### 5.4 无障碍

- 颜色对比 ≥ 4.5:1 (文字对背景)
- 交互元素键盘可达
- `prefers-reduced-motion` 兼容(关闭滚动联动高亮动画)
